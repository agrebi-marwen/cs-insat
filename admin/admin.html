Competitive Programming Judge

These settings appear because the category is CP. Accepted submissions are graded automatically by the Piston API.

100 to 5000 ms. Java automatically gets +2000 ms for JVM startup.

1 to 256 MB. Java always gets at least 256 MB, Python at least 64 MB.

Recommended: each test is given to the program on its own, exactly like the examples in the statement, so beginners just read the input and print the answer. Choose t test cases only if the statement says the input starts with t. The test file is the same in both cases.

When enabled, failed attempts can be retried. Accepted challenges still award points only once.

Attach test_cases.json with a tests list: one { input, expected } entry per sub-test (an input can span several lines, e.g. a matrix). The judge builds the Codeforces-style input itself: t (the number of tests) on the first line, then every test's input, and runs the user's code once against it. Example: 

{
  "tests": [
    { "input": "0 0 0\n0 1 0\n0 0 0", "expected": "0" },
    { "input": "1 0 0\n0 0 0\n0 0 0", "expected": "2" }
  ]
}

Add "sample": true to the tests that appear as examples in the statement: participants can run their code on those with Run on samples (nothing is recorded). Sample tests are still part of the graded run.

The older single { "input": "t\n...", "expected": "..." } object is still accepted (no samples).

Decimal answers (e.g. 0.333333) are accepted within an absolute or relative error of 10-6; say so in the statement. Integers and words must match exactly.

Space-separated tags prefixed with # (e.g. #BinarySearch #MLOps).
